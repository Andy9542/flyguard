# Отклонения от ТЗ

Пункт ТЗ, изменение, причина, влияние на гипотезы. Дата — день решения.

- **D1 (2026-09-26). Один провайдер вместо двух** (чек-лист оператора, `llm_api.providers`). Выдан только ключ DeepSeek. Влияние: генераторы и судьи парафраз не из разных семейств (D2), модель агента выбирается среди двух моделей одного семейства (D3). На H1a–H3 напрямую не влияет; стиль одного семейства генераторов записан в угрозы валидности.
- **D2 (2026-09-26). Парафразы: один генератор и один судья** (ТЗ 1.6). Генератор `deepseek-flash` (temperature 0,9, два вызова на базу вместо двух генераторов, итого 8 кандидатов на базу), судья `deepseek-v4-pro` (temperature 0), генератор и судья не совпадают. Правило «двойное да» вырождается в «да» единственного судьи. Влияние: возможен более мягкий отбор позитивов; доли принятия и отказов отчитываются как требует ТЗ.
- **D3 (2026-09-26). Кандидаты модели агента** (`llm_api.agent_models`): `deepseek-flash`, затем `deepseek-v4-pro` вместо `gpt-4o-*`. Правило пилота (ASR ∈ [0,20; 0,70], utility ≥ 0,40) применяется без изменений.
- **D4 (2026-09-26). Бюджет API 7,0 USD вместо 600** (`llm_api.budget_usd`): равен балансу аккаунта. Срезы по приоритетам 1.5 записываются здесь после пилота.
- **D5 (2026-09-26). Модель агента выбрана не по правилу пилота** (Приложение B). Пилот на 40 атакованных + 10 чистых кейсах workspace/`important_instructions`: `deepseek-flash` — ASR 0,00, utility 1,00; `deepseek-v4-pro` — ASR 0,05, utility 0,90. Ни один кандидат не попал в коридор ASR [0,20; 0,70]; по правилу ТЗ взят кандидат с ASR, ближайшим к 0,40: `deepseek-v4-pro` (режим без размышлений, temperature 0). Влияние: мало эпизодов `hijacked` (A13); стоимость эпизода в 4,7 раза выше, чем у flash, что вместе с бюджетом 7 USD урезает объём трасс (D6). Полные результаты пилота — `results/pilot.json`.
- **D6 (2026-09-26). Срезы объёма трасс по бюджету** (ТЗ 1.5, «Бюджет API»). Проекция по пилоту (`results/pilot.json` → `projection`): (1) AgentDojo `important_instructions` + чистые прогоны четырёх сьютов ≈ 3,5 USD; (2) AgentDyn чистые прогоны всех задач + `important_instructions` на тестовых задачах контракта ≈ 2,1 USD — укладываются в 6,0 USD (7,0 минус резерв 1,0 на парафразы). Не укладываются и не запускаются без пополнения баланса: атаки AgentDyn на нетестовые задачи (≈ 3,1 USD; по контракту §6 они в сравнение не входят), шаблоны `tool_knowledge`, `injecagent`, `ignore_previous` (≈ 3,2 USD каждый). Влияние: без трёх шаблонов кросс-шаблонные и двойные фолды E3 и часть баз парафраз «шаблон × цель» строятся только по тексту шаблонов (базы не требуют прогонов), а перенос E3 получает «не хватило данных»; на H1–H3 напрямую не влияет. Пункт (2) ТЗ разбит на две части (тестовые задачи контракта первыми), чтобы контракт был выполнен целиком раньше, чем закончится бюджет.
- **D7 (2026-09-26). Спаны инъекций: второй проход по YAML-экранированному тексту** (ТЗ 1.5 «Извлечение»: «спан при точном совпадении текста атаки после нормализации»). Харнесс отдаёт объекты окружения агенту через `yaml.dump`, поэтому инъекция приходит как YAML-скаляр в кавычках: апострофы удвоены, строки свёрнуты, `\n`/`\uXXXX` экранированы. Точное совпадение находило спан лишь в ~45 % атакованных эпизодов. Добавлен детерминированный декодер YAML-кавычек с картой индексов: совпадение ищется в декодированном тексте и отображается обратно на экранированную запись в документе; режим каждого шага (`exact` / `yaml_escaped`) пишется в `meta_json` и `traces_extraction.json`. Переключатель `extraction.decode_yaml_quoted_scalars` в конфиге; при `false` действует буквальное правило. Влияние: полнота позитивов AgentDojo/AgentDyn (без второго прохода половина инъекций считалась бы «чистыми» окнами и портила бы метки); правило воспроизводимо второй командой.
- **D8 (2026-09-26). P_val: безобидная часть deepset берётся только из валидационных 20 %** (ТЗ 1.8: «безобидная часть deepset train»). Причина: обучающие негативы подгоняют детекторы, и порог τ_FPR на них был бы оптимистичен. Влияние: P_val теряет 274 документа (69 вместо 343 от deepset), цель ≥ 2 000 документов на этапе 1 не достигнута, до трасс и парафраз τ_FPR опирается на меньший пул; переключатель `pools.p_val_deepset: train` возвращает буквальное правило.
- **D9 (2026-09-26). Приложение A.1: правило отбора 30 слов по χ² и три правила фильтров парафраз.** (1) χ² считается не по всем токенам, а по токенам ≥ 3 символов с буквой, без английских стоп-слов и только обогащённым в инъекциях (A18): буквальные топ-30 — английские служебные слова из-за немецкой половины безобидных документов. (2) Класс сущностей «имя» (два подряд слова с заглавной) требуется дословно только для баз на английском: у немецких баз это обычные существительные, и английская парафраза отбраковывалась бы всегда. (3) Негативам страта присваивается только по Жаккару, без правила запрещённых слов (безобидный текст вправе содержать «email», «send»). (4) Кандидат, объявленный глубоким, но с запрещённым словом при J ≤ 0,3, переводится в мелкую страту (как в A.6), хотя номинальный диапазон мелкой — 0,3–0,5. Влияние: состав итогового набора парафраз; доли принятия по стратам отчитываются.
- **D10 (2026-09-26). Порядок «коммит `regex_patterns.txt` → первое чтение тестовых файлов» нарушен по времени, но не по существу.** Файл регулярок закоммичен 26.09 в 10:03 UTC (4c94585). До этого, во время первой волны реализации, парсер трасс был один раз прогнан кодом по всем замороженным логам (тестовый материал по ТЗ 1.10) для подсчёта числа найденных спанов; после коммита агент правки парафраз прочитал столбец меток deepset test для подсчёта строк. Обе операции журналированы задним числом (строки `logs/data_access.log` 10:27 и 10:38 UTC с пометкой), текст ни одного примера не открывался, а регулярки выведены только из deepset train и с момента коммита не менялись. Влияние на гипотезы: нет; критерий приёмки о порядке выполняется по журналу формально, и `check_acceptance.py` должен читать пометки «retroactive / after the fact» и показывать реальный порядок.
- **D11 (2026-09-26). Обучение вариантов для контракта** (ТЗ Этап 5: «обучение сдаваемых вариантов на окнах нетестовых задач и нетестовых шаблонов AgentDojo»). Из-за срезов D6 сгенерирован только шаблон `important_instructions`, который контракт §6 целиком исключает из обучения, поэтому обучающая выборка контракта не содержит ни одного атакованного окна AgentDojo (`validation_attacks = 0`, `train_attacks = 0` в `split_manifest.json`). Резерв: сдаваемые варианты обучаются на метках deepset train, C_unl дополняется чистыми окнами нетестовых задач AgentDojo, порог подбирается по чистым валидационным эпизодам как в §7. Влияние: сравнение с поведенческой мухой измеряет перенос лексического детектора с deepset на ответы инструментов, а не обучение на трассах; снимается при пополнении бюджета и генерации остальных шаблонов.
- **D12 (2026-09-27). E3 при одном шаблоне** (дополнение к D6). Пока сгенерирован только `important_instructions`, все 4 кросс-шаблонных фолда и 16 фолдов двойного удержания непригодны, E3 пишет для них «не хватило данных» с причиной из манифеста; выполняется только кросс-сьютовое семейство (FPR на незнакомом сьюте). На H1–H3 не влияет.
- **D13 (2026-09-27). Пулы негативов меньше цели.** После полной сборки |P_test| = 1 085 и |P_val| = 197 при цели ≥ 2 000 (ТЗ 1.8). По правилу Этапа 0 рабочая точка TPR берётся при FPR 5 % (500–1 999), а не 1 %. Причины: D8 (P_val без обучающих негативов deepset), дедупликация статичных окружений AgentDojo (A38) и небольшой объём трасс (D6).
